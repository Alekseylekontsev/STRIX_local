# Условия тестирования локального HERMES на Strix Halo

> **Обновление 26 октября 2026:** текущий HERMES Agent требует минимум 64 000 токенов контекста. Исторические API-бенчмарки ниже выполнялись с 32 768 и не проверяли этот порог агента. Рабочий сервер и настройки HERMES исправлены на **65 536**. Штатный CLI/gateway-запрос с обычным набором инструментов успешно вернул `LOCAL_OK`; реальный runtime context проверен через `/props`. Исторические результаты скорости ниже не пересчитаны и остаются замерами 32K.

Дата Linux-тестов: **25 октября 2026**, часовой пояс Europe/Warsaw.

## 1. Что сравнивали

Проверяли локальную цепочку обработки документов: PDF → изображение страницы → OCR → категоризация → embeddings → ChromaDB → поиск. Отдельно проверяли прямое чтение изображений двумя мультимодальными моделями.

Windows и Ubuntu установлены на **разных SSD одного ПК**, используется dual boot. Это сравнение сохранённых конфигураций на одном CPU/GPU, **не контролируемый A/B-тест операционных систем**: версии runtime, кванты, настройки thinking, размеры контекста и выборки отличаются. Последовательного запуска идентичного набора под обеими ОС в этот день не было.

В первоначальной vision-проверке раздела 7 использовались **штатные проекторы** (после дополнительной проверки Gemma переключена на F16, см. раздел 9):

Обновлённый файл с тем же именем нельзя считать гарантированно идентичным. В частности, опубликованный сейчас Qwen Q6 отличается по размеру от локального тестировавшегося файла.

## 4. Начальный тест скорости шести моделей

Температура 0; `chat_template_kwargs.enable_thinking=false`; один запрос за раз.

1. Запрос `Reply with OK only.`, лимит 16 токенов: время до первого токена после переключения/загрузки модели.
2. Прогретый запрос, лимит 160 токенов:

   > Explain how to safely update a Linux system. Give a numbered list of practical steps with brief explanations. Write at least 200 words.

3. Проверка JSON с `17*23`, сортировкой `[9,2,5]` и столицей Польши, лимит 100 токенов.

Запрос на 200 слов намеренно ограничивался 160 токенами для замера; полнота текста не оценивалась. Использовался streaming; first token считался по первому content/reasoning delta. Скорость генерации — серверное `timings.predicted_per_second`, не полное время обработки запроса.

| Модель | Генерация, токен/с | Прогретый первый токен, с | Первый токен при старте, с |
|---|---:|---:|---:|
| Bonsai Q1 | 37,01 | 0,42 | 3,71 |
| Muse Glimmer | 12,65 | 0,67 | 13,25 |
| Gemma Q4 | 11,61 | 0,50 | 13,50 |
| Qwen Q6 | 8,45 | 0,54 | 17,99 |
| Qwen Q8 | 7,15 | 0,69 | 22,30 |
| Qwen BF16 | 4,20 | 0,75 | 36,91 |

Это одиночные короткие прогоны, не рейтинг качества. Все, кроме Muse, завершили JSON-проверку. Muse не выдал итоговый JSON в пределах 100 токенов. Для разных моделей длина в токенах не равна одинаковому объёму полезного текста.

Qwen Q8 обработал 10 документов. Для честного сравнения остальных моделей использовалась общая подвыборка 5 документов: автономность AI, анонимизация, ISO toolkit, blockchain consultation, русский Hermes guide.

Категории проверялись по тематическим ожиданиям, не независимой слепой разметке. Для статьи про автономность допустимы и ai_research, и ai_security. Ошибка `mixed` у англоязычной ISO-таблицы у трёх моделей связана с кириллическим мусором в OCR; Bonsai относил к `mixed` все пять документов.

### Основная база: более качественное извлечение

Использован постраничный **PDF layout text**, а при отсутствии пригодного текста — OCR PNG **300 dpi**. Native text выбран на 23 страницах, OCR — на 7. Пригодность native text: не менее 80 буквенно-цифровых символов и менее 1% replacement characters; это эвристика, а не полная валидация текстового слоя.

На 13 заранее выбранных фразах: базовый OCR сохранил 9/13; выбранное извлечение — 13/13. **Это не 100% OCR accuracy, не CER/WER и не полная проверка таблиц.** Связи строк/столбцов для ответственных чисел требуют сверки с изображением.

Embeddings: `Qwen3-Embedding-0.6B-Q8_0.gguf`, GPU, `--embedding --pooling last --ctx-size 8192 --parallel 1`. Основная ChromaDB 1.5.9 — отдельная persistent-коллекция `shareddata_primary`, cosine distance. Фрагменты по 1600 символов, шаг 1400, границы страниц сохраняются; метаданные содержат источник, страницу и способ извлечения. Итог — **55 фрагментов**. Базовая OCR-коллекция хранится отдельно: 1800 символов, шаг 1600, 30 фрагментов; из-за разных границ чанков эти коллекции не являются строго изолированным A/B-тестом извлечения.

Шесть контрольных запросов к основной базе дали нужный документ на первом месте: автономность AI, анонимизация, Hermes по-русски, AI worms, ISO 27001 7.5, blockchain consultation. Это маленькая ручная выборка, не общая оценка retrieval accuracy.

В HERMES база подключена через MCP `documents_primary`, инструменты `search_primary_documents` и `primary_documents_status`. Проверены handshake, discovery, реальный поиск и `hermes mcp test documents_primary`. **Полный каталог не проиндексирован:** только первые 3 страницы этих 10 PDF.

## 8. Сравнение с сохранёнными Windows-замерами

Источник Windows: отчёт `DST/Hermes/strix-halo/benchmark-results-20260707.md` и исходный `benchmark-lmstudio.py` на общем SSD. Дата: 7 июля 2026. Указаны тот же Ryzen AI MAX+ 395 / Radeon 8060S, Windows Ultimate Performance, LM Studio runtime `llama.cpp-win-x86_64-amd-rocm-avx2@2.24.0`, загрузка `--gpu max -c 8192 --parallel 1`.

| Windows-модель | Квант | Медиана токен/с | Комментарий отчёта |
|---|---|---:|---|
| Qwen3.6-35B-A3B | Q4_K_M | 52,396 | 5 прогонов, 256 токенов, скрытое reasoning |
| Qwen2.5 Coder 32B | Q4_K_M | 8,347 | 3 прогона, видимый текст |
| Gemma 4 31B QAT | Q4_0 | 5,217 | 3 прогона, reasoning, нет видимого текста в лимите |

**Qwen3.6-35B-A3B — MoE с малой активной частью; его 52 токена/с нельзя сопоставлять с dense Qwen3.8-27B как доказательство преимущества Windows.**

Исходный Windows-скрипт повторён под Linux на текущей Gemma: warmup 64 токена, 3 прогона по 256 токенов, temperature 0.2, один и тот же prompt:

> Generate a compact benchmark paragraph about local AI performance. Do not use markdown. Continue until you reach the token limit.

Медиана Linux — **11,529 токена/с**, около **2,21x** от сохранённой Windows Gemma. Это `completion_tokens / полное время запроса`, а не `timings.predicted_per_second` из раздела 4. Контекст Linux 32K против Windows 8K; GGUF Unsloth UD-Q4_K_XL против Q4_0; runtime и кванты различаются. Оба режима не дали видимого текста в лимите. Проверка Linux-ответа подтвердила наличие `reasoning_content`, хотя счётчик `reasoning_tokens` скрипта показывал ноль: старый скрипт не учитывает этот формат канала. Поэтому 2,21x — разница двух сохранённых конфигураций в генерации токенов, **не ускорение готового ответа и не чистый выигрыш Ubuntu над Windows**.

Повторены те же 10 PNG 200 dpi и 30 вопросов раздела 7, при temperature 0, max_tokens 180, thinking off. Это повтор **той же выборки**, не новая независимая валидация.

Отдельный прогретый текстовый запрос из раздела 4, 160 выходных токенов, temperature 0, thinking off: Qwen Q4_K_M — **12,77 токена/с генерации** по серверному `timings.predicted_per_second`. Это один прогон; он отличается от `completion_tokens / полное время`, используемого в Windows-скрипте.

## 10. Что нужно для строгого Windows/Ubuntu A/B

1. Те же физические CPU/GPU, питание, BIOS и доступная GPU-память.
2. Те же GGUF и projector, проверенные SHA-256; одинаковый способ размещения на SSD.
3. Один commit llama.cpp с максимально сопоставимыми backend/build flags и актуальными драйверами.
4. Одинаковые context, KV cache, Flash Attention, batch/ubatch, GPU offload, threads, parallelism и thinking.
5. Те же PNG и точные размеры, prompts, schema, лимит выходных токенов и seed/temperature.
6. Раздельно cold load, warm first token, image encoding, prefill, generation и полное время полезного ответа.
7. Не менее 5 повторов; медиана и разброс. Число токенов и видимый ответ учитывать раздельно.
8. Для качества — независимый эталон транскрипции, CER/WER, сохранение таблиц и правильность чисел/связей. Текущие точечные проверки его не заменяют.

Практический выбор на дату отчёта: Ubuntu с уже проверенным локальным конвейером; Gemma — основная, Qwen Q8 — запасная. Это эксплуатационное решение по текущим измерениям, не утверждение о превосходстве ОС при идентичных условиях.
